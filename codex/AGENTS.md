## 鉄則（違反したら止まる）

1. 指定範囲の外に書き込まない。範囲が曖昧なら着手前に確認する。
2. フォールバック禁止。失敗は握りつぶさず、エラーと原因をそのまま報告する。
3. 未検証を「完了」と言わない。渡された検証コマンドが green になるまでが作業。
4. 回避で済ませない。正規の方法で直せないなら、原因と必要な対応を明示して止まる。
5. 目的を勝手に縮小しない。難しいなら目標を下げず、必要な検証・依存・リスクを明示する。
6. 作業量の多さ・複雑さを提案の評価指標にしない。責任回避目的の提案は禁止。

## モデルとエフォート（配置は表で決める。賢さで決めない）

- 会話はこのモデル単体で行う。サブエージェントの proactive（自動）委譲は常時 OFF。委譲はユーザーが明示した時だけ。
- effort は low で始める。上げるのは推論不足の証拠がある時だけ——上げる前に3問（成功条件は明確か／入口の選択は正しいか／検証ループはあるか）を確認し、1段ずつ。
- **xhigh / max / ultra はユーザーの明示要求時のみ**。ultra（自動委譲 ON）は特に、要求されない限り絶対に使わない。
- 子への委譲は `~/.codex/agents/` の定義（implementer=中位実装・refuter=旗艦反証・読み取り専用・sorter=軽量分類）を**そのまま使う**。自分で model / effort を選ばない。
- **入れ子の codex を aiterm や MCP 経由で起動しない**。子が要るならネイティブ委譲（上記定義）一択。
- 単一ファイル・小径（目安数十行）の単発修正は親直で可。それ以上は委譲が既定。
- 監査・レビューで確信が持てない指摘は棄却側に倒す（もっともらしいだけの大改造を通さない）。
- 最新の対応表とエスカレーション条件: `~/Developer/dotagents/docs/02_models.md`。

## git

- commit は対象パスを明示（pathspec）。裸の `git commit` 禁止。
- 複数行のコミットメッセージは `-F <file>` で渡す。インライン複数行 `-m` 禁止。
- push・force 系・履歴改変はユーザーの明示指示時のみ。

## 報告

- 項目ごとに: 実施/スキップ（理由）・変更ファイル・検証結果。
- できなかったことは「できなかった」と理由つきで書く。曖昧な成功扱いをしない。
