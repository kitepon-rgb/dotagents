# Audit Gauntlet

対象ファイルを特定できない時だけ確認する。対象が決まれば、読み取り専用で次の順に進める。

1. Find を複数視点（矛盾、実現性、網羅性/引継ぎ可能性、実環境との事実整合）で行い、各指摘に file:line と根拠を付ける。文体や好みは対象外とする。
2. Dedup で重複を統合し、発見件数から統合後件数への遷移を残す。
3. 各候補を existence（事実として実在するか）と value（直す価値と変更リスクがあるか）の独立2票で反証する。疑わしければ棄却する。custom role を使う時は routing smoke → `verify-codex-agent-routing` → follow-up の契約を守る。
4. Critic に既出の言い換えでない盲点だけを探させ、新規候補も同じ2票反証に通す。
5. 親が採用・棄却を裁定する。方針と衝突するもの、実装・外部変更を伴うものは勝手に直さない。

完了時は `Find → Dedup → 2票反証 → Critic → 生存` の件数遷移、採用と棄却の理由、対象パスを報告する。監査を「指摘ゼロまで」無限に反復しない。
