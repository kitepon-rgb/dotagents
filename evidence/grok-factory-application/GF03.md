## GF04の所有repo分割案

GF03監査pass後のLattice revisionで、現GF04を次の2工程へ分割する。両方をGF05の前提にし、同一repo writerは各1工程だけとする。

### Spotter工程

- 範囲: `src/hooks/lib.mjs`とClaude hook入口、`test/hooks.test.mjs`
- 挙動差: Grok形のcommon keysを持ちClaude snake_case keysを持たないenvelopeは、Spotter未対応hostとして無出力・exit 0。Claude/Codexの既存経路は不変
- 負系fixture: SessionStart、UserPromptSubmit、PreToolUse、Stop、SessionEndのGrok形入力がdaemon・DB・tool deny・Stop continuation・runtime errorを起こさない
- focused gate: `test/hooks.test.mjs`、`test/codex-hook-cmd.test.mjs`、`test/parent-output-projector.test.mjs`

### Throughline工程

- 範囲: `src/session-start.mjs`、`src/prompt-submit.mjs`、`src/turn-processor.mjs`とhook entrypoint test
- 挙動差: Grok形のcommon keysを持ちClaude snake_case keysを持たないenvelopeは、Throughline未対応hostとして無出力・exit 0。Claude/Codexのcapture・handoffは不変
- 負系fixture: SessionStart、UserPromptSubmit、StopのGrok形入力がDB・state・VS Code task・runtime errorを作らない
- focused gate: `src/hook-entrypoints.test.mjs`、`src/runtime-error-hook.test.mjs`、`src/cli/codex-hook.test.mjs`

両工程ともprovider payloadをClaude形へcanonicalizeしない。判定は「対応外のenvelopeを起動しない」ためだけに置き、Grok host enum、transcript、tool DB、auditor backend、installer、diagnosticsを増やさない。

## 棄却を維持する案

| 案 | 棄却理由 |
| --- | --- |
| Spotter正式Grok host化 | 観測された欠陥は互換hookの誤起動であり、Grok上でSpotter監査を提供する要求・tool catalog・auditor契約は存在しない |
| Spotter tool DB / auditor / installer / diagnostics拡張 | 非ブロック境界には不要で、未検証の正式対応を成功に見せる |
| 共通canonicalizer | SpotterとThroughlineのClaude契約をGrokへ誤適用し、provider固有境界を消す。必要なのは変換でなくunsupported no-op |
| Grok transcript reader / 9 row dedupe | Aitermの現行sourceとtestはassistant群の順序保持を明示する。dedupeはvendor transcriptの情報を失う |
| gpt-connector多provider化 | 今回のrequest、hook、terminal、transcript経路に存在せず、修理集合を変えない |
| 未使用grok-stop-hookや工場installer拡張 | 新しい実測がなく、GF01原因と無関係 |
