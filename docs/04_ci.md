# 04_ci — lint ゲート（CI＝作業の安全網）

<!-- 前提: Fable 級統括（2026-07 時点）。構造の敷設（PLAN.md 原則1②）＝最上位知能の使い所。 -->

dotagents は同期ハブ＝**壊れた install.sh / bin スクリプトが全端末へ配布される**リスクを持つ。それを止める最小の安全網が本 lint ゲート。ローカルと CI は完全ゲートとして **`make ci`** を同じように回す（[01_project-layout.md](01_project-layout.md) 必須要件「テスト＋CI」）。`make lint` はその静的 lint と hook smoke だけを回す部分ゲートである。

## ローカルで回す（正典）

```sh
make ci         # CI と同一: lint + clean HOME install/config test
make lint       # shell + python + markdown + 共通憲法 + skill/hook smoke
make lint-sh    # shellcheck: install.sh + bin/*.sh + tests/**/*.sh
make lint-js    # node --check: bin/*.mjs
make lint-md    # markdownlint: 生きた正典の md
make lint-constitution # CLAUDE.md / AGENTS.md の共通章一致
make lint-skills # Codex skill の静的契約
make lint-hooks # Claude / Codex hook の空打ち smoke
make test-install # 隔離 HOME の install/profile/config apply（Codex CLI 必須）
make test-update  # cron 最小 PATH から NVM 配下の npm を解決
make test-oracle  # Oracle互換rollback wrapperのNode/entry/Chrome入口をOS非依存で検証（通常入口ではない）
make test-factory-reporter # factory reporter のprivacy/outbox/retry契約
```

- 依存: **shellcheck**（`brew install shellcheck`。macOS で未導入だった実績あり）・**ripgrep (`rg`)**（skill smoke の検索入口）・**node/npx**（markdownlint-cli2 を npx 経由・バージョン固定 `@0.23.0`）・**python3**・**Codex CLI 0.144.1**（`make ci` / `make test-install` が実 parser として使う。CI は `@openai/codex@0.144.1` を明示導入）。
- 合格＝`make ci` の全ゲート exit 0・指摘 0。shell・md に加え、共通憲法5章（人格・応対・五原則・報告・出力衛生）の逐語一致、cron最小PATHからのNVM/npm解決、Oracle互換wrapperのOS非依存なrollback入口、factory reporterのprivacy/outbox/retry契約を検証する。通常のChatGPT入口はgpt-connector正本に従う。

## shellcheck（shell）

- 対象: `install.sh`、`bin/*.sh`、`tests/**/*.sh`。既存 smoke の `A && B || C` に限る SC2015 は、テスト自身が fail 状態を集計して最後に終了する意図的な形のため除外し、他は既定ルールのまま維持する。
- shell は本数が少なく密度も低いので既定ルールで green を維持できる＝厳格側に置く。

## markdownlint（docs）— 緩い安全網

- 設定: [`.markdownlint-cli2.jsonc`](../.markdownlint-cli2.jsonc)（リポ直下）。対象は**生きた正典と配布 skill**＝ルート `CLAUDE.md`/`README.md`・`claude/CLAUDE.md`・`claude/skills/**/*.md`・`codex/AGENTS.md`・`codex/skills/**/*.md`・`shared/**/*.md`・`docs/**/*.md`。`docs/archive/**`（凍結）と `node_modules/**` は除外。
- 方針: **正しく描画される既存の知識文書と戦わない**。純スタイル系の4ルールだけ無効化し、構造系（見出し階層・見出し前後空行・末尾改行・ハードタブ・空リンク 等 ~40 ルール）は既定のまま残す＝将来の編集の破綻は捕まえる。
- **無効化した4ルールと根拠**（勝手に有効へ戻さない・戻すなら既存文書の一括修正とセットで裁定する）:

| ルール | 内容 | 無効化の理由 |
|---|---|---|
| MD013 | line-length（80桁） | 日本語散文＋広い表に固定桁は不適。折り返しは可読性を下げる |
| MD060 | table-column-style | 表パイプ整列の見た目のみ。意味に無関係 |
| MD040 | fenced-code-language | ASCII ツリー図・テキスト断片に言語指定は無意味 |
| MD031 | blanks-around-fences | リスト内フェンス（GitHub で正常描画）にだけ発火する摩擦 |

- 無効化前は 176 指摘（MD013×138・MD060×30・MD040×4・MD031×4）＝全て上記4ルール。無効化で doc を一切変更せず 0 指摘に到達（content churn ゼロ）。

## 共通憲法一致

- `bin/verify-constitution-parity.sh` が `claude/CLAUDE.md` と `codex/AGENTS.md` のツール非依存な5章を抽出し、逐語比較する。
- Codex 固有差分はモデル配置・ネイティブ委譲・shell 入口・push 制約の章に隔離する。共通章を片方だけ変えると `make lint` が fail する。

## CI（[.github/workflows/ci.yml](../.github/workflows/ci.yml)）

- トリガー: `push` to `main`＋全 `pull_request`。`permissions: contents: read`（最小権限）。
- job `lint`（ubuntu-latest）: `ripgrep` を明示導入し、ランナー同梱の `shellcheck` / `node` と合わせて `tool versions` ステップで存在を確認（欠けたら fail-loud・黙って skip しない）→ `@openai/codex@0.144.1` を明示導入して `codex --version` で確認 → `make ci`（lint・skills・hooks・隔離 HOME の profile/config apply）。
- npx が `markdownlint-cli2@0.23.0` を都度取得（固定版＝ルール変更でゲートが勝手に赤/緑にならない）。

## 拡張の指針

- shell/docs を足したら glob は自動で拾う（`bin/*.sh`・`docs/**/*.md`）。新しい docs サブディレクトリ（`audit-YYYY-MM/` 等）も対象に入る。
- Node.js の配布scriptは`bin/*.mjs`を`node --check`し、factory reporterはfake BugHubを使う動的testも通す。
- 別種の lint（yaml・json 等）を足すなら Makefile に `lint-<kind>` を増やし `lint` の依存に足す＝ローカルと CI が同時に追従する。
