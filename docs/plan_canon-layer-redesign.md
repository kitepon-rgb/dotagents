## 設計の要点（3行）

1. 規則は**3層に一度だけ**置く: L0常時ロード=判断トリガーと肯定制限文だけ／L1起動時=局面契約／L2オンデマンド=手順・詳細。
2. **L0は約70%痩せる**（実測23.7千字→試算7.2千字）。規則は消えない——層を移るだけ。削除は導出可能な重複だけ。
3. 矛盾（凍結台帳P1〜P8）は**移設時に目標層で一度だけ**解消する。パッチを現行構造に当てない。

## 文字数予算（裁定事項）

- 案: **憲法正本≦4.5千字・リポ直下AGENTS.md≦2.5千字**（試算+余裕10%）。
- 機構: render時にwc検査→超過は`make lint`で**警告**（FAILにするかは運用実績を見て再裁定）。

## 移行の実行規律（節単位で原子的に）

1. 受け皿を作りcommit → 2. 逐語で複写しcommit（二重存在=安全） → 3. L0をトリガー行＋ポインタへ
置換（矛盾はここで解消・確定裁定を適用） → 4. generator再生成＋generation test/skill smoke/parityの
exact文言追従（gate接触126箇所はワークシートでマーク済み） → 5. refuter 1巡（読者面消失検査を必須
観点に） → 6. 親受入・push。中途状態でセッションを跨がない。

## wave構成（裁定後）

- wave 0: 受け皿5面の新設（中身は複写元の逐語＋見出しのみ。ここでは何も消えない）
- wave 1: 憲法の節単位移行（計画文書の作法→調査と知識→git鉄則→報告の順・毎節で規律1-6）
- wave 2: AGENTS.md・PLAN.md（原則番号・骨子は不変、本文の厚みだけ移す）
- wave 3: L1контract群の細部L2化（retry手続き等・小規模）
- wave 4: 予算lintの敷設・凍結台帳Tier 2（機械gate工事）の個別起票
