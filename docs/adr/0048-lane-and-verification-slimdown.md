# ADR 0048 — 統括レーンの発動条件と検証頻度を製品成果優先へ絞る

- 日付: 2026-07-16
- 状態: accepted

## 文脈

監査・テスト・台帳整合などのメタ作業が製品進捗を圧迫していた（オーナー実測: 24時間で製品コード1,000行未満）。統括レーンの発動条件が広く（単一repoのドキュメント整理にもControlが立つ）、検証構造（反証・Critic・2票制・多段監査）が全作業へ複利で掛かっていた。2026-07-14／07-15の頻度裁定は統制文書の追記で対処したため、肥大が止まらなかった。

## 決定（オーナー裁定 2026-07-16）

- **統括レーン（Control・ADR・独立監査・Packet）は、複数repo・複数Executor・複数Phaseが実際に揃う戦役だけ**で発動する。それ以外はすべて通常レーン。H操作の承認・高リスク操作の説明義務はレーンに関係なく維持する。
- **委譲は統括昇格ではない**。通常レーンでもWorker（implementer等）へのコーディング委譲は可能で、Packetなしの明確な指示と親のdiff・test確認で受け入れる。
- **反証・Critic・2票制は統括レーンの契約クリティカル（F相当）だけ**に限定する。それ以外は親確認で足り、確信できない指摘は棄却する。
- **テストはfocused＋完了時related 1回**。full regressionは統括レーンのPhase gateとCI必須gateだけ。
- 適用先: `shared/constitution.md`「作業レーンと統制」「テストは薄く速く」、`shared/orchestrate/contract.md`「使う時・使わない時」「統括ゲート1」「監査の頻度」、orchestrate SKILL「検証2票制」。07-14のレーン定義・07-15のテスト頻度裁定の該当部分を置き換える。

## 影響と戻し方

メタ作業の既定コストが下がり、品質保証は契約クリティカルへ集中する。戻す場合は本ADRと適用先条文を同じ単位でrevertする。
