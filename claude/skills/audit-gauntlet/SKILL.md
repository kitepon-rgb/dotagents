# audit-gauntlet

文書を **1 本の Workflow** に通して磨き込む。書いた本人と同じ視点では盲点を再度見落とすため、監査は独立 context のサブエージェント群に投げ、**もっともらしい指摘ほど反証にかけ、生き残りだけを採用する**。

## 引数

対象ファイルのパス（絶対パス推奨・複数可＝相互参照する文書群はまとめて渡す）。

引数なしで呼ばれた場合は会話文脈から対象を推定する:

- 直前にユーザーまたは Claude が作成・編集・言及した文書ファイル
- 「この計画書を」等の指示語があればその指示先
- 1 つに絞れたら「対象: `path` で進める」と 1 行宣言して進める。絞れない場合のみユーザーに確認

## フロー（Workflow 1 本・関門は並列化済み）

```
[文書] → Find（並列4視点） → Dedup → Verify（critical を敵対的反証） → Critic（盲点検査＋追加検証）
      → 統括が裁定 → 外科的修正 → （修正が大きい場合のみ第2ラウンド） → 完了報告
```

### 4 視点（Find）

1. **矛盾**: 文書内・文書間で論理的に両立しない記述
2. **実現性**: 技術的に不可能・前提が事実と異なる・明示された制約と両立しない（実環境を読み取り検証してよい・読み取り専用）
3. **網羅性・構造・引き継ぎ可能性**: 工程の欠落・順序破綻・会話文脈なしで読めない記述・根拠のない方針
4. **事実整合**: 文書の事実主張を実環境（ファイル・git・設定）と実測突合。**文書が「無い」と言う物が実在する逆方向も検査**

### 実装

Workflow ツールで以下の構造のスクリプトを起動する（2026-07-04 実証済みの型。プロンプトは self-contained に書き、会話履歴を渡さない）:

- 各 Find エージェント: 対象パスを Read させ、`{findings:[{quote,file,issue,severity,evidence}]}` の structured output。「critical は実行者を誤った行動に導く級のみ。文体・好みは対象外。ゼロなら空配列」
- Dedup: プレーンコードで `file+quote 先頭80字` キー統合（エージェント不要）
- Verify: **critical のみ** 1 件ずつ refuter（読み取り専用 agentType）へ——「この指摘を殺せ。誤り・些末・文書が既に扱っている・引用が文脈無視なら refuted=true。**迷ったら棄却側**」。minor は反証せず統括の裁定に直行
- Critic: 生存指摘と minor 一覧を渡し「この監査に欠けている観点だけを挙げよ（既出の言い換え禁止）」→ 新規 critical は同じ Verify に通す

### 裁定と修正（統括＝呼び出し側の責務）

- 生き残った critical は原則採用して**外科的に修正**（全面書き直し禁止）。反証者が「指摘の核心は正しいが副次主張は過剰」と精密化してきたら、その精密化に従う
- minor は統括が価値対工数で裁定（採用/棄却を明示）
- **オーナーの方針と衝突する指摘はオーナーに裁定を仰ぐ**（例: 時間見積ベースの指摘——dotagents/PLAN.md は見積を判断材料にしない方針）
- 修正が文書の骨格に及んだ場合のみ第 2 ラウンド（Workflow 再実行）。軽微な字句修正では回さない

## 完了報告

- Find→Verify→Critic の件数遷移（発見→dedup→生存）
- 採用した critical と主要 minor の要約（各 1 行）
- 棄却した指摘とその理由（反証が効いた例は価値が高い＝1 行で残す）
- 対象ファイルパス。git 管理下なら `git diff <file>` で差分確認できる旨を一言

## やらないこと

- 外部プラグイン（ECC 等）への依存（原則: ネイティブ Workflow で完結。dotagents/PLAN.md 原則7）
- 無限ラウンド（監査は非決定的で、回すたびに新指摘が湧き得る。**「指摘ゼロまで収束」は保証できない**——反証と裁定で打ち切るのが正）
- スタイル・誤字修正（責務外）・文書外への中間ログ保存（git で追える）
