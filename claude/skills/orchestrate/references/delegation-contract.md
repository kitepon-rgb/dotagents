# 委譲契約テンプレート（8点セット）

委譲プロンプトはこの骨子を埋めて作る。**8点のどれかを省くと、そこから品質が漏れる**（特に⑦再検証義務は省略事故が多い）。標準実装者 `implementer` エージェントには①〜②と⑤〜⑧の共通部が焼き込み済みなので、③④⑥の個別部だけ書けばよい。

```
リポジトリ <絶対パス>（ブランチ <name> チェックアウト済み。**ブランチ切替・git commit 禁止**）。

① 対象範囲: 任務は <ディレクトリ/ファイル群> のみ。この外に触らない（読み取りは可）。
② 変更の性質: 外部挙動不変が絶対（例外があるなら1件ずつ明示）／挙動修正枠なら「何がどう変わるか」を報告に明記。

③ 仕様: <やること。file:line 証拠つきで。監査ダイジェスト等の共通入力ファイルがあればパスを渡し「該当項を読んでから着手」と書く>

④ 罠チェックリスト: <このタスク固有の既知の罠。例:「409 は Zod 検証の後に保つ（先に置くと 400→409 に化ける）」「キー挿入順は契約（{idx, ...spread} 禁止）」>

⑤ characterization 規約（テスト系のみ）: これは現在の実挙動の固定である。テストが期待と違う結果を返したら**期待を実挙動に合わせる**（プロダクションコードを直さない）。明白なバグに見えたら直さず報告に記載。

⑥ 検証: <コマンド列> が全 green になるまで。<DB等の接続情報>。

⑦ 前提の再検証義務: 渡した仕様・監査結果・行番号も鵜呑みにしない。着手直前に grep/実読で再確認し、食い違いは（勝手に方針変更せず）報告に明記した上で実態に従う。

⑧ 報告フォーマット: 項目ごとに 実施/スキップ（理由）・変更ファイル・<タスク固有の要求（対応表・棚卸し表・挙動差の明文 等）>・検証結果。
```

## 統括側のチェックリスト（委譲後）

- [ ] 報告の「実施/スキップ」と diff が一致するか（diff --stat → 要点精読 → 逐語移設は削除行↔新ファイルの照合）
- [ ] ゲートを**自分で**再実行（typecheck / テスト / E2E）
- [ ] コミットは対象パスだけ `git add` → `git status` 確認 → `-F <file>` メッセージでコミット
- [ ] 委譲先の「発見」（前提の誤り・想定外の実挙動）を計画・記憶へ反映
